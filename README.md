# ARTEx Agent Profiles for Claude Desktop

English · [한국어](README.ko.md) · [日本語](README.ja.md) · [简体中文](README.zh.md)

An integration repository for using ARTEx from a local Claude Desktop session. It packages Claude agent profiles, skills and commands together with Python MCP connectors for an operator-configured ARTEx server.

> Use the connectors only with an ARTEx instance and assessment tasks you are authorized to access. The target-request connector is scope and budget constrained, but it is not a general-purpose scanner. Review the task scope, allow/deny rules, request budget and stop conditions before enabling target requests.

## What is included

- `claude-cowork-plugin/agents/`: role profiles for coordination, planning, assessment, reporting and retesting
- `claude-cowork-plugin/skills/`: reusable ARTEx workflow, API reconnaissance, browser and scope guidance
- `claude-cowork-plugin/commands/`: assessment workflow command
- `src/artex_agent/`: read-only, evidence-writing, task-setup and target-request MCP connectors
- `tests/`: offline connector tests
- `scripts/package_cowork_plugin.py`: builds a plugin ZIP under `dist/`
- `scripts/smoke_mcp_stdio.py`: checks MCP startup and tool listing without writing to ARTEx or contacting a target

## Requirements

- Python 3.11 or newer
- Claude Desktop with a compatible local plugin/MCP workflow
- A separately installed and running ARTEx server

This repository does not include the ARTEx server, a Claude account, API keys, credentials, or task data. Claude session authentication and ARTEx's own LLM configuration are separate runtimes.

## Local connector setup

1. Create and activate a Python virtual environment from this repository.
2. Install the connector package: `python -m pip install -e .`.
3. Copy `claude-cowork-plugin/.mcp.json.example` into the plugin's local configuration and replace the placeholder Python and source paths with absolute paths on your computer.
4. Set `ARTEX_API_BASE_URL` to your ARTEx server URL. Store credentials through the provided `artex-auth-store` command; do not place secrets in the MCP JSON or source control.
5. Install the plugin ZIP generated by `python scripts/package_cowork_plugin.py` using the plugin installation flow supported by your Claude Desktop version.

The example MCP configuration is a template. Review the resulting connector list and permissions in Claude Desktop before using it.

## Checks

Run the offline test suite with:

```powershell
python -m unittest discover -s tests -v
```

Run the local MCP handshake check with:

```powershell
python scripts/smoke_mcp_stdio.py
```

The smoke check starts local MCP processes and lists their tools; it does not prove end-to-end access to an ARTEx deployment. Use a designated synthetic task for write/readback testing and do not create synthetic vulnerability findings.

## Runtime boundary

Agent profiles run in the Claude Desktop session that invokes them. They can call the configured local MCP connectors. This integration does not pass Claude subscription credentials to ARTEx's native planner or worker runtime, and does not enable unattended ARTEx execution by itself.
