# ARTEx → Claude Cowork capability matrix

Source audit basis: ARTEx sidebar (`Container/ARTEX/artex-source-backup/web/src/navigation/sidebar/sidebar-items.ts`), native Task detail tab implementation, server routes, current Cowork MCP source, and Anthropic Help Center/runtime documentation rechecked 2026-10-16. This is source/runtime mapping, not Cowork account acceptance. Cowork's model session uses the Claude subscription; local plugin MCP processes run on the desktop and connect to ARTEx, which receives no Claude credential. Per current Anthropic docs, new Cowork tasks may run in the cloud, while local MCP connectors are available through Claude Desktop and require the Desktop broker to remain online; local MCP processes do not run inside Anthropic's cloud sandbox. A Cowork task must be started from Desktop for local plugin MCP access; do not require the agent loop itself to run locally. Remote MCP is another supported plugin path but requires Anthropic's cloud to reach a public URL; exposing this private 127.0.0.1:8787 ARTEx service is not part of this implementation. Claude-plan use for the Agent SDK is currently documented, but that SDK drives/bundles the Claude Code CLI runtime; the user requires Cowork only and disallows CLI, so the SDK route is excluded by the user's runtime constraint.

## Claude subscription/runtime boundary (verified 2026-10-16)

- Cowork runs in the cloud by default for new tasks on current plans; local plugin MCP connectors work through Claude Desktop, which brokers access to local servers. Keep Desktop open and start the task there. A cloud-only session without the Desktop broker cannot reach ARTEx at 127.0.0.1:8787. Managed-device policy can disable local MCP. [Cowork architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview) · [Cowork surfaces](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile) · [Local vs remote connectors](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors)
- Anthropic's October 7, 2026 update says eligible Claude plans can use the Agent SDK under plan limits/monthly credits. The SDK drives and bundles the Claude Code CLI runtime. Since the user explicitly requires Cowork and disallows CLI, no SDK/CLI runtime is embedded in ARTEx; this is a user-selected runtime boundary, not a subscription-policy prohibition. [Agent SDK plan support](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) · [Agent SDK runtime](https://platform.claude.com/cookbook/claude-agent-sdk-08-dynamic-workflows)
- A remote connector is technically another option, but Anthropic's cloud must reach the MCP endpoint over the public internet. This project does not expose or tunnel the private ARTEx 8787 instance. [Remote MCP requirements](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
- In the supported Cowork path, the plan authenticates Claude's model session. Local MCP tools authenticate only to ARTEx using the user's local ARTEx credential; no Claude subscription token is forwarded to ARTEx. ARTEx-native LLM profiles, planner/worker scheduling, and token accounting remain separate.
